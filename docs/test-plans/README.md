# برنامهٔ تست گردش فروش

## اجرای تست‌ها

از ریشهٔ `bnpl-sales-system` اجرا کنید:

```powershell
npm run test:unit
npm run test:smoke
npm run test:all
```

- `test:unit` ابتدا API را build می‌کند و تست‌های منطق/سرویس را با `node:test` و mock سبک Prisma اجرا می‌کند. به پکیج تست تازه نیاز ندارد.
- `test:smoke` به PostgreSQL، API و رابط محلی نیاز دارد. فقط loopback را می‌پذیرد؛ یک راننده و چند کاربر موقت می‌سازد، مسیر فروش را اجرا می‌کند، راننده را آرشیو و حساب‌های تست را غیرفعال می‌کند.
- `test:all` دو گروه را پشت سر هم اجرا می‌کند.
- تست smoke به محیط تولید وصل نمی‌شود. برای اجرای آن از اطلاعات واقعی راننده استفاده نکنید.

## مرز پوشش فعلی

اسموک، API واقعی و تراکنش‌های PostgreSQL را از شروع پرونده تا تکمیل، مدارک، تسویه و آرشیو می‌آزماید. پاسخ ۲۰۰ صفحهٔ وب نیز بررسی می‌شود؛ تعامل واقعی با کنترل‌های React، مرورگرهای مختلف، صفحه‌خوان و چیدمان در اندازه‌های متفاوت را پوشش نمی‌دهد. این موارد در برگهٔ «چک‌لیست دستی» فایل اکسل هستند.

تست‌های واحد، قواعد ورودی و نقش، ادغام پیش‌نویس، ثبت رویداد، یک گذار مرحله، محدودیت فایل و کنترل تلاش ورود را جدا از دیتابیس می‌آزمایند. آزمون‌های وضعیت‌های کامل گردش در اسموک قرار دارند تا قانون نقش‌ها و تغییرات پایگاه داده نیز همزمان بررسی شود.

## چرا گزارش رویدادها یک فهرست بلند است؟

صفحهٔ رویدادها دفتر سراسری حسابرسی است و رویدادهای همهٔ پرونده‌ها، کاربران، مدارک و تأییدها را به ترتیب زمان کنار هم می‌آورد. endpoint فعلی حداکثر ۵۰۰ ردیف را یکجا می‌دهد و رابط آن فیلتر یا صفحه‌بندی ندارد؛ بنابراین برای دیدن ردپای کل سامانه مفید است ولی برای پیدا کردن یک رویداد مشخص کند و شلوغ می‌شود. پیشنهاد بعدی، فیلتر راننده/کاربر/نوع/بازهٔ تاریخ و صفحه‌بندی است. تاریخچهٔ مربوط به یک راننده باید در صفحهٔ پروندهٔ همان راننده بماند.
