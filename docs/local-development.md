# راه‌اندازی محلی سامانه

این راهنما برای اجرای روزمرهٔ سامانه در ویندوز است و فرق بین باز شدن صفحهٔ وب و آماده بودن API و دیتابیس را روشن می‌کند.

## اجرای معمول روی این رایانه

این مخزن یک دیتابیس محلی در پوشهٔ نادیده‌گرفته‌شدهٔ `.local-db` دارد. اتصال برنامه در `api/.env` روی `127.0.0.1:5434` تنظیم شده است. سرویس PostgreSQL ویندوز یا دیتابیس Docker ممکن است پورت دیگری مثل `5433` داشته باشد؛ روشن بودن آن به‌تنهایی به معنی آماده بودن دیتابیس این پروژه نیست.

### ۱. دیتابیس پروژه را روشن کن

PowerShell را از ریشهٔ مخزن (`D:\SABA\codebase\bnpl-sales-system`) باز کن و وضعیت دیتابیس اختصاصی پروژه را ببین:

```powershell
$pgBin = 'C:\Program Files\PostgreSQL\16\bin'
& "$pgBin\pg_ctl.exe" -D .local-db status
```

اگر پیام `no server running` دیدی، دیتابیس را با پورت مورد انتظار پروژه روشن کن:

```powershell
& "$pgBin\pg_ctl.exe" -D .local-db -l .local-db\local-postgres.log -o "-h 127.0.0.1 -p 5434" start
& "$pgBin\pg_isready.exe" -h 127.0.0.1 -p 5434
```

خط آخر باید `accepting connections` نشان دهد. اگر نشان نداد، گزارش خطا را در `.local-db/local-postgres.log` ببین. دیتابیس جداگانهٔ ویندوز یا Docker را با این دیتابیس قاطی نکن؛ آن‌ها ممکن است پورت و گذرواژهٔ متفاوت داشته باشند.

### ۲. API را در ترمینال اول اجرا کن

```powershell
npm run dev:api
```

صبر کن تا NestJS پیام آماده‌شدن برنامه را بدهد و خطای اتصال Prisma/PostgreSQL دیده نشود. API روی `127.0.0.1:3001` اجرا می‌شود.

اگر پورت `3001` از قبل در اختیار برنامهٔ دیگری است، به‌جای متوقف‌کردن برنامهٔ ناشناس، API را روی `3002` اجرا کن:

```powershell
$env:PORT = '3002'
npm run dev:api
```

### ۳. رابط وب را در ترمینال دوم اجرا کن

از همان ریشهٔ مخزن، در یک پنجرهٔ PowerShell دیگر. اگر API روی پورت پیش‌فرض `3001` است:

```powershell
npm run dev:web
```

ترمینال باید نشانی `http://127.0.0.1:5174/` را نشان دهد. اسکریپت خودش host و port را تعیین می‌کند؛ آرگومان اضافه مثل `--host 127.0.0.1` به آن نده، چون ممکن است Vite آن را مسیر برنامه برداشت کند و به‌جای صفحهٔ اصلی پاسخ 404 بدهد.

اگر API را روی `3002` اجرا کردی، پیش از اجرای وب proxy را هم به همان پورت وصل کن:

```powershell
$env:API_PROXY_TARGET = 'http://127.0.0.1:3002'
npm run dev:web
```

صفحه را در مرورگر با این نشانی باز کن:

```text
http://127.0.0.1:5174/
```

حساب محلی این رایانه `local-admin` است. گذرواژه را فقط از `LOCAL_DEMO_PASSWORD` در `api/.env` بخوان؛ آن را در مستندات یا پیام‌ها کپی نکن.

## راه‌اندازی اولیه یا پس از تغییر دیتابیس

برای این رایانه، بعد از روشن‌کردن `.local-db` و پیش از اجرای API، این فرمان‌ها را از ریشهٔ مخزن اجرا کن:

```powershell
npm install
npm run db:generate
npm run db:migrate
```

`npm install` برای نصب اولیه یا وقتی وابستگی‌ها عوض شده‌اند لازم است. `db:migrate` را فقط برای ساخت/به‌روزرسانی schema دیتابیس توسعهٔ محلی اجرا کن. فایل `api/.env` محلی است و نباید وارد Git شود.

## تشخیص سریع خطا

| نشانه | بررسی و راه‌حل |
| --- | --- |
| مرورگر می‌گوید سایت در دسترس نیست | مطمئن شو `npm run dev:web` هنوز در ترمینال دوم در حال اجراست؛ نشانی باید `127.0.0.1:5174` باشد. |
| صفحهٔ وب 404 می‌دهد | فرمان وب را از ریشهٔ همین مخزن و بدون آرگومان اضافه اجرا کن. خروجی باید مسیر ریشهٔ `http://127.0.0.1:5174/` را نشان دهد. |
| صفحه باز می‌شود ولی پیام `Unexpected token '<'` می‌بینی | پاسخ API به‌جای JSON صفحهٔ HTML است. معمولاً پورت proxy به برنامهٔ دیگری وصل شده؛ API و `API_PROXY_TARGET` را روی یک پورت تنظیم کن و Vite را دوباره اجرا کن. |
| صفحه باز می‌شود ولی ورود/داده‌ها کار نمی‌کنند | API را در ترمینال اول بررسی کن. در حالت عادی Vite درخواست‌های `/api` را به `127.0.0.1:3001` می‌فرستد؛ اگر API روی `3002` است، وب را با `API_PROXY_TARGET` اجرا کن. |
| API خطای اتصال یا `P1001` می‌دهد | `pg_isready` را برای پورت `5434` اجرا کن. اگر آماده نیست، مرحلهٔ دیتابیس را انجام بده و گزارش `.local-db/local-postgres.log` را بخوان. |
| API خطای احراز هویت دیتابیس یا `P1000` می‌دهد | احتمالاً API به PostgreSQL دیگری وصل شده یا اطلاعات `DATABASE_URL` در `api/.env` با دیتابیس `.local-db` یکی نیست. از گذرواژهٔ سرویس پورت `5433` برای دیتابیس پورت `5434` استفاده نکن. |
| API می‌گوید پورت `3001` اشغال است | برنامهٔ اشغال‌کننده را با `Get-NetTCPConnection -State Listen -LocalPort 3001` شناسایی کن. برنامهٔ ناشناس را متوقف نکن؛ API را روی `3002` و وب را با `API_PROXY_TARGET=http://127.0.0.1:3002` اجرا کن. |

برای بررسی پاسخ API از همان مرورگر یا PowerShell، این مسیر باید JSON برگرداند:

```text
http://127.0.0.1:5174/api/auth/setup-status
```

اگر این مسیر خطای شبکه/۵۰۰ می‌دهد ولی `/` باز می‌شود، مشکل از اتصال API یا دیتابیس است، نه از بالا نیامدن صفحهٔ وب.

## خاموش‌کردن

در هر ترمینال `Ctrl+C` بزن تا همان سرویس متوقف شود. برای خاموش‌کردن دیتابیس اختصاصی پروژه:

```powershell
& 'C:\Program Files\PostgreSQL\16\bin\pg_ctl.exe' -D .local-db stop
```

## اجرای روی رایانهٔ دیگر با Docker

برای رایانه‌ای که `.local-db` آماده ندارد، از دستورالعمل Docker در [README](../README.md#آماده‌سازی-روی-رایانهٔ-دیگر-با-docker) استفاده کن. در آن حالت Docker پورت `5433` را منتشر می‌کند و `DATABASE_URL` در `api/.env` باید به همان پورت اشاره کند؛ تنظیم `5434` مخصوص دیتابیس محلی آمادهٔ این رایانه است.
